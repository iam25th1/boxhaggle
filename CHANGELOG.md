# Changelog

All notable changes to BOXHAGGLE. Dates are UTC.

## [Unreleased]

### Fixed

- Merchant x402 paywall and `/mcp`: real PayBox payments on Solana were refused as `invalid_exact_svm_transaction_simulation_failed` and nothing was charged. Evidence: PayAI's `invalidMessage` for them is `Simulation failed: "BlockhashNotFound"`; both rejected payments decode to a sound transaction (fee payer slot left for PayAI, valid payer signature, `TransferChecked` of 10000 at 6 decimals into the payTo token account, a memo nonce) that simulates cleanly on mainnet once its blockhash is replaced; their blockhashes ran out 14 and 16 seconds before the paid retry reached the merchant, which was 42 and 46 seconds after PayBox signed. A blockhash lives 150 slots, measured at 214 ms each (about 32 seconds). The merchant now keeps the facilitator's `invalidMessage` (bounded, encoded runs cut, logged as `detail`), refuses such a payment as `payment_expired`, and a refused paid `/mcp` call returns its reason, the state, fresh requirements and the retry step in its text and `AGENT DATA`. Payment instructions and the tool descriptions ask the agent to send the paid retry as its very next action. Every existing check is unchanged. Regression test from the decoded transaction layout.
- `packages/core` `agentText`, `agentDataBlock` and `parseAgentData`: every tool result's text can now end with a labelled `AGENT DATA` JSON block for agents that never see `structuredContent`. A real test in Claude web stalled at round 00 because Claude passes `structuredContent` to the MCP App view, not to the model, and the text held no session id. The block escapes backticks and refuses floor or salt fields before the reveal.
- `/mcp`: all four tools end their text with `AGENT DATA` (session id, state, budget, next step). Unpaid `haggle_offer` and `haggle_checkout` texts carry the x402 `accepts`, `resource` and `x402Version` exactly as quoted, the amount, and a one-line pay-then-retry instruction; `haggle_reveal` adds the floor, salt and verdict. `structuredContent` is unchanged, so the counter view works as before. Tool descriptions say where the values are.
- `apps/plugin`: every tool ends its text with `AGENT DATA`. The PayBox portal test of `boxhaggle_open_session` had no session id in its text. Proposal texts carry the exact `io.paybox/transactionProposal` and the next step from PayBox's guide (follow the PayBox request to its end, then read status or reveal); the proposal tools' structured output is still the starter's single key. Rebuild and upload the new `dist/plugin.mjs`.
- Text frames no longer cut long lines with an ellipsis. A real PayBox portal test of `boxhaggle_open_session` showed the footer as `No offers yet. Each offer is a paid x40...`. Every free-text line now word wraps inside the 46-column border, long tokens such as hashes break across lines, label values wrap under the value column, the receipt prints the full commitment instead of a shortened one, and ledgers past 8 rounds show the latest 8 plus a `+N earlier rounds` line. Rebuild the plugin and upload the new `dist/plugin.mjs` to the portal.

### Changed

- The live demo is self-hosted: web at `https://boxhaggle.25th.dev`, merchant at `https://boxhaggle-api.25th.dev`, both on loopback behind a dedicated Cloudflare tunnel. `docs/SELF-HOSTING.md` is a generic guide (any process manager, any reverse tunnel, loopback binds, the `CF-Connecting-IP` trust rule, the env var list with placeholders) and replaces the host-specific deploy notes. README deploy section rewritten to match; Railway configs kept and marked as the alternate.
- Merchant and web servers bind `127.0.0.1` by default (`HOST`); the alternate Dockerfiles set `HOST=0.0.0.0` for container networking.
- `SECRET_MODE=raw` skips the one-time token request. `start:env` scripts (`node --env-file=.env`) for agent and merchant keep secrets out of shell history.

### Security

- The web server sends `Cache-Control: no-transform`, so the CDN cannot rewrite pages (the 25th.dev zone was injecting an analytics script, which the strict CSP then blocked with a console error). The CSP is unchanged.
- Merchant rate limits key on `CF-Connecting-IP` when `TRUST_CF_CONNECTING_IP=1`, and only for requests whose peer is loopback (the local cloudflared, directly or through a loopback proxy). From any other peer the header is ignored, so a client cannot rotate a spoofed IP past the limits. Tests cover both cases. Production refuses a non-https `WEB_ORIGIN` and refuses `TRUST_PROXY` and `TRUST_CF_CONNECTING_IP` together.
- Plugin sessions (payment-gated, no merchant key on paid routes) bind to their first verified payer; payments from any other payer are refused after verify and before settlement. Plugin session ids are never announced on the lobby stream. Closes a griefing path where a stranger could pay small fees to burn another player's patience.

### Added

- `docs/PROOF.md`: the first real haggle on Solana mainnet (2026-10-17, Orange Rotary Phone): the five 0.01 USDC offer fees and the 1.28 USDC checkout with their signatures and Solscan links, each read back from mainnet into the payTo token account, the 0.01 USDC account-opening transfer labelled as setup, the final payTo balance (1.34 USDC), the commitment, the revealed floor (1.07) and salt with the VERIFIED recomputation, and receipt `BH-005FF7E9`. Linked from the top of the README.
- PayBox `use_service` (gateway mode) for the MCP App, so PayBox signs and re-fetches within seconds and the 30 second Solana blockhash window stops depending on how fast the model copies `x_payment`. New keyless routes `POST /mcp-pay/offer/:sessionId?round=N&offerUsd=D.CC` and `POST /mcp-pay/checkout/:sessionId?round=N` take MCP sessions only, read everything from the URL (the unpaid probe has no body), refuse unknown or repeated query fields and any non-empty body, hold the spend cap, and forward in process to `/offer` and `/checkout`, so every existing check applies: amount, asset, network, payTo, resource bound to session and round, single-use nonce, first-payer binding, rate limits, `payment_expired`. The paid response carries the Broker's reply, the session state and the frame. Unpaid `haggle_offer` and `haggle_checkout` now return `useService` (url and method) with a `use_service` instruction in text and AGENT DATA; `pay_x402` stays as `fallback`. New free `haggle_status` returns the state, frame and AGENT DATA and is linked to the counter, which animates what happened since the last result. Tool descriptions say so.
- `haggle_start` defaults to `brass-compass` and a 3.00 USD cap, so `haggle_start {}` opens a counter.
- In-chat counter as an MCP App. The merchant serves `/mcp` (streamable HTTP, stateless) with `haggle_start`, `haggle_offer`, `haggle_checkout` and `haggle_reveal`, each linked to `ui://boxhaggle/counter` and each returning the text frame for hosts without MCP Apps. Sessions follow the plugin rules (payer bound, off the lobby, rate limited) and carry a spend cap. The counter UI (`apps/web/counter.html`, built by `npm run build:counter` into one self-contained HTML file with embedded OFL fonts) reuses the web app's Broker, split-flap board, fuse, printer, coin tray, PayBox docket and reveal, animates each tool result's new events, and makes no network connection.
